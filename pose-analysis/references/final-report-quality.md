# 最终报告质量标准

## 目标

本文件用于 Codex 在读取脚本生成的报告骨架、姿态 JSON 和专项知识库后，补全最终教练专业版报告。

最终报告必须让教练能复核，让家长能理解，让孩子看到时不被羞辱。

## 报告必须回答的问题

每份可评分或部分可评分报告必须回答：

1. 本次视频是否适合评分，为什么。
2. 本次最重要的 1-3 个技术问题是什么。
3. 每个问题的证据是什么，出现在什么阶段或时间点。
4. 这些问题如何影响专项表现。
5. 下一周怎么练，教练如何观察是否改善。
6. 下次拍摄和复测哪些指标。
7. 和同模板历史相比，进步、退步和稳定项是什么。

## 禁止内容

不得输出：

- 没有证据的确定性结论。
- 医疗诊断。
- 成人高强度训练处方。
- 羞辱式标签。
- 与视频无关的泛泛励志话。
- 把报告写成科普文章而不是训练复盘。

## 证据写法

推荐写法：

```text
在 00:03.20-00:03.80 的弓步完成阶段，前膝没有明显形成稳定制动，姿态 JSON 中右膝角度仍接近伸直区间；这说明本次推进更多依赖跨步而不是后腿推进后的稳定落地。
```

不推荐写法：

```text
孩子下肢力量不足，需要加强力量训练。
```

原因：第二句没有证据，也没有区分技术、力量、机位和动作理解。

## 最终报告结构

可评分报告：

```markdown
# <项目>-<动作模板> 技术分析报告

## 一、拍摄质量与结论
## 二、总评
## 三、评分表
## 四、动作阶段诊断
## 五、主要问题排序
## 六、训练建议
## 七、下次追踪指标
## 八、历史对比
## 九、拍摄建议
## 十、隐私说明
```

不可评分报告：

```markdown
# <项目>-<动作模板> 拍摄质量报告

## 一、不可评分结论
## 二、不可评分原因
## 三、仍可保留观察
## 四、重新拍摄方案
## 五、下次文件名建议
```

## 评分表要求

评分表必须包含：

- 维度
- 分数
- 权重
- 证据
- 主要扣分原因
- 下次追踪指标

如果某维度证据不足，写 `证据不足`，不要给分。

## 训练建议要求

训练建议必须满足：

- 一周内可执行。
- 每项建议对应一个问题。
- 不超过 4 个重点。
- 有教练观察口令。
- 有复测方式。

格式：

```markdown
### 练习 1：<名称>
- 目的：
- 做法：
- 教练观察：
- 停止/降级条件：
- 下次复测：
```

## 语言风格

使用教练专业语言：

- 直接指出问题。
- 用证据支撑。
- 不用夸张形容。
- 不把儿童训练问题人格化。

示例：

- 用“前脚落地稳定性不足”，不用“腿软”。
- 用“路线前半段手臂屈肘停留过多”，不用“太依赖蛮力”。
- 用“深蹲底部骨盆控制不足”，不用“核心太差”。

## 终稿自检

报告发送前逐项检查：

- 是否先给出质量门槛。
- 是否标注置信度。
- 是否所有评分都有证据。
- 是否明确哪些维度证据不足。
- 是否包含下次追踪指标。
- 是否做了同模板历史对比或说明暂无历史。
- 是否默认匿名。
- 是否没有医疗诊断。
